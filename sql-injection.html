LAB 01 - APPRENTICE

WHERE clause: Hidden Data Retrieval

Explicación Técnica: Se identificó que el parámetro category es vulnerable. El sistema captura el texto del usuario e inserta directamente la instrucción en la base de datos sin sanitización. Esto permite reescribir las reglas de negocio que dictan qué información es pública.

Procedimiento: 1. Intercepción con Burp Suite. 2. Inyección del payload en el parámetro category. 3. Análisis de respuesta 200 OK con incremento de datos, confirmando que la base de datos ignoró los filtros de visibilidad programados.

' + OR 1=1 --

Análisis del Payload: La comilla (') cierra el campo de texto. OR 1=1 es una verdad universal que obliga al sistema a devolver todos los registros. El comentario (--) anula la restricción AND released = 1.

LAB 02 - APPRENTICE

Authentication Login Bypass

Explicación Técnica: Vulnerabilidad de severidad crítica en la función de inicio de sesión. El parámetro username carece de validación, permitiendo que un agente externo altere la regla lógica para que el sistema compruebe solo la existencia del usuario, anulando el requisito de contraseña.

Procedimiento: Se intercepta la petición POST, se sustituye el valor de username por el vector de ataque y se asigna un valor arbitrario a password. El servidor responde con un 302 Found y un token de sesión de administrador.

administrator'--

Listing database contents (Non-Oracle)

Objetivo: Enumerar el esquema interno para comprometer la cuenta.

Procedimiento Paso a Paso: 1. Consulta a information_schema.tables para hallar la tabla users_qbvywo. 2. Mapeo de columnas mediante information_schema.columns identificando username_pqbuks y password_uqpynv. 3. Extracción final de credenciales en texto plano.

LAB 11 - PRACTITIONER

Blind SQLi with conditional responses

Explicación Técnica: La aplicación altera su comportamiento visual (mensaje "Welcome back") si la consulta es verdadera. Esto permite realizar preguntas lógicas (Verdadero/Falso) para extraer información letra por letra de forma indirecta.

Procedimiento: Se usó un enfoque de búsqueda binaria automatizada mediante un script para iterar sobre las 20 posiciones de la contraseña.

TrackingId=... ' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='administrator') > 'm

Credencial Extraída: zp5jy1l5taltb3wm7m9l.

LAB 13 - PRACTITIONER

Visible error-based SQL injection

Explicación Técnica: Se aprovecha que el servidor muestra errores detallados. Al usar CAST() para intentar convertir la contraseña (texto) en entero, la base de datos genera un error de conversión que incluye el valor sensible (la contraseña) en el mensaje devuelto al cliente.

' AND 1=CAST((SELECT password FROM users LIMIT 1) AS int)--
LAB 16 - NO TERMINADO

Out-of-band Interaction (OAST)

Motivos de interrupción: Requiere Burp Collaborator (versión Professional). Se intentó usar Interactsh, pero el firewall de salida (egress filtering) de la academia bloqueó la interacción con dominios no autorizados.

Análisis Técnico: La falla reside en la capacidad de inyectar comandos de Oracle que permiten la resolución de entidades externas XML para exfiltrar datos.

' UNION SELECT EXTRACTVALUE(xmltype('...'),'/l') FROM dual--

CONCLUSIONES DEL ROADMAP

El análisis sistemático demostró que las inyecciones SQL (In-band, Blind y OOB) comprometen severamente la confidencialidad e integridad de la información al evadir mecanismos de autenticación y extraer credenciales administrativas.

Mitigación Principal: Implementación obligatoria de Consultas Parametrizadas (Prepared Statements) para neutralizar la ejecución de código malicioso en el motor SQL.
